Task 2 part (b): a case where strict inclusion breaks.

No. Back-invalidation only removes copies that are already in L1/L2. A block that is still
in flight towards L1/L2 when the LLC evicts it is not found, and it arrives afterwards:

E1: line X misses in L2C; the request goes to the LLC and hits there
E2: the LLC sends X up; the response sits in L2C's MSHR / fill queue (in flight)
E3: line Y misses in the LLC, and X is chosen as the eviction victim
E4: back-invalidation looks for X in L1I, L1D and L2C, finds no copy, removes nothing
E5: the LLC evicts X
E6: the in-flight response arrives and X is filled into L2C (and L1D)
Now X is in L2C but not in the LLC, so strict inclusion is broken.

The same happens with a writeback in flight: L1D's dirty copy of X sits in L2C's write
queue while the LLC evicts X (and L2C's copy); the writeback then misses in L2C and fills X
there, so X is in L2C but not in the LLC.

Task 2 part (d): which misses go down with an inclusive LLC? (at most 4 words)

LLC WRITEBACK misses

With an inclusive LLC, every block that L2C writes back is still in the LLC, so a
writeback always hits there. LLC WRITEBACK misses drop to 0 (soplex 4 -> 0, mcf 2 -> 0,
from make lru vs make task2).
